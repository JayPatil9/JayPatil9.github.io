## Z mod 2: The Simplest Field

Linear Algebra, at its heart, is about *any* collection of objects where you can meaningfully define "addition" and "scaling."

To see why, let's build the simplest possible number system from scratch.

Imagine you have only two values: **0** and **1**. And the only rule for adding them is:

| + | 0 | 1 |
|---|---|---|
| **0** | 0 | 1 |
| **1** | 1 | 0 |

That last entry, `1 + 1 = 0`, is the only place this differs from regular arithmetic. You can think of it as addition where you "wrap around" after 1, or equivalently, **addition modulo 2**.

This system has a name: **ℤ₂** (read: "Z mod 2"). It's the simplest field that exists. It has only two elements (0 and 1) and the rule is that any arithmetic operation is taken mod 2.

<p style="border-top: 1px dashed currentColor; margin-top: 1em; margin-bottom: 1em;"></p>
**Key insight:** In ℤ₂, every element is its own additive inverse. That is, `a + a = 0` for every `a`. So "subtraction" and "addition" are the same operation. (Although, we are currently only talking about one dimension, but this can be extended to higher dimensions, don't worry I'll explain it in detail.)

---

## Vectors over ℤ₂

Now let's build vectors out of these two values.

A **vector** in ℤ₂ᵈ is just a list of `d` values, each being 0 or 1. For example, in ℤ₂³:

```
v = (1, 0, 1)
w = (0, 1, 1)
```

**Adding two vectors** is done coordinate-by-coordinate, with each coordinate computed mod 2:

```
v + w = (1+0, 0+1, 1+1) = (1, 1, 0)   [mod 2]
```

Every `d`-bit integer is a vector in ℤ₂ᵈ, and XOR-ing two integers is vector addition in this space.

<p style="border-top: 1px dashed currentColor; margin-top: 1em; margin-bottom: 1em;"></p>
**Key insights:** 

1) Now we know that vector addition in ℤ₂ᵈ is equivalent to XOR operation on integers. From this we can interpret that, integers can be viewed as (d-dimensional) vectors in ℤ₂ᵈ.

2) Usually, to do subtraction in a vector space, we need to find the additive inverse of a vector. But in ℤ₂ᵈ, every vector is its own additive inverse. So "subtraction" and "addition" are the same operation.

3) Think on this: `(7 * V1) = V1`. I think this example is enough to prove that taking coefficients in ℤ₂ᵈ is equivalent to taking coefficients in {0, 1}. So "scaling" a vector by a scalar is equivalent to either including it or excluding it.

Let that sink in for a moment, because the rest of everything builds on it.

---

## Span

Given a set of vectors, the **span** is the set of all vectors you can make by adding subsets of them together (in ℤ₂, "scaling" by 0 or 1 just means "exclude" or "include").

Formally, for vectors v₁, v₂, …, vₙ ∈ ℤ₂ᵈ, the span is:

```
span({v₁, ..., vₙ}) = { c₁v₁ ⊕ c₂v₂ ⊕ ... ⊕ cₙvₙ : cᵢ ∈ {0, 1} }
```

This is exactly the set of all **XOR-sums of subsets** of your original numbers.

**Example:**

Take the set `{5, 3}`, i.e., `{101, 011}` in binary.

- Empty subset: `0`
- `{5}`: `101`
- `{3}`: `011`
- `{5, 3}`: `101 ⊕ 011 = 110 = 6`

So `span({5, 3}) = {0, 3, 5, 6}`.

Most competitive programming problems involving XOR subsets are really asking: **what is the span of this set of vectors?** How many elements does it have? What's the maximum element? Is some specific value `x` in the span?

---

## Linear Independence

Not all vectors in your set are equally "useful." Some might be redundant, they can already be reached by XOR-ing other vectors in the set.

**Definition:** A set of vectors `{v₁, ..., vₙ}` is **linearly independent** if no vector in the set can be written as a XOR-sum of others in the set.

<p style="border: 1px dashed currentColor; padding: 1em">
Equivalently: <a style="font-style: italic; font-weight: bold;">No non-empty subset (of linearly independent vectors) XORs to zero.</a>
</p>

Before moving forward, take a break and try to prove this equivalence. It is a good exercise to understand the concept of linear independence. (Also try to prove that  no two distinct non-empty subsets of linearly independent vectors can XOR to the same value.)

**Example:**

- `{4, 2, 1}` = `{100, 010, 001}` → independent. No subset XORs to 0 (they each have a unique bit).
- `{3, 5, 6}` = `{011, 101, 110}` → NOT independent. `3 ⊕ 5 ⊕ 6 = 0`.

Why does independence matter? Because the moment a vector is "reachable" from the others, it doesn't expand the span at all. Adding it to your set gives you nothing new.

---

## The Basis, The Minimal Spanning Set:

A **basis** of a set of vectors is a subset that is:
1. **Linearly independent**, and
2. **Has the same span** as the full original set.
3. **Minimal in size** (no smaller subset has the same span).

In other words, it's the *smallest* set of vectors that can reach everything your original set can reach.

**Why does this matter?**

Suppose you start with `n = 10⁵` numbers. Their span could be huge to think about directly. But if you find a basis of size `b`, where `b ≤ d` (the number of bits), then:

- The span has exactly **2ᵇ** elements (one for each subset of the basis).
- Every question about "which XOR-sums are reachable" reduces to a question about `b ≤ d` or so vectors, not `n`.

This is the compression that makes hard problems tractable.

---

## Finding the Basis, Gaussian Elimination over ℤ₂

<p style="border-top: 1px dashed currentColor; margin: 1em;">
    Before we get into the algorithm, I recommend you to revise the steps that are involved in forming the row echelon form of a matrix.
</p>

Here is the algorithm. It processes vectors one by one and maintains a basis of all vectors seen so far.

The key invariant: we keep at most one basis vector for each bit position, and that vector is the *only* basis vector with a `1` in that position (the others have been zeroed out at that position).

Just like row echelon form, we will try to eliminate the highest set bit of the vector we are trying to insert using the basis vectors we have already inserted. If we are able to reduce it to 0, then it is already in the span and we don't need to insert it. Otherwise, we will insert it into the basis.

```cpp
int basis[30] = {};  // basis[i] = basis vector whose highest set bit is i

void insert(int v) {
    for (int i = 29; i >= 0; i--) {
        if (!(v >> i & 1)) continue;   // bit i not set in v, skip

        if (!basis[i]) {               // no basis vector here, insert v
            basis[i] = v;
            return;
        }

        v ^= basis[i];                 // eliminate bit i from v using basis[i]
    }
    // If v becomes 0, it was already in the span, no new basis vector needed
}
```

<p class="spare-me" style="border-radius: 5px; border-top: 15px solid #f12a2a; background-color: #e98888; padding: 0.5em;">
<b>Note:</b> The above code is a simplified version of the algorithm. In practice, you may want to keep track of the size of the basis and other details depending on your use case.
</p>

**What is this doing intuitively?**

We're trying to "place" the vector `v` in the basis. We look at its highest set bit, say bit `i`. If there's already a basis vector at position `i`, XOR-ing `v` with it eliminates bit `i` from `v` (leaving a smaller vector). We keep going down. If `v` hits 0, it was already reachable. If it survives, it has a highest bit `i` that no current basis vector occupies, so we plant it there.

**This is Gaussian Elimination** over ℤ₂, the exact same algorithm used on matrices.

**Time Complexity:** `O(n · d)` where `d` is the number of bits (typically 30 or 60).

---

## Properties of the Basis You'll Reach For Often

Once you've built the basis, following facts are immediately seemingly obvious, but are worth stating explicitly:

**1. The number of distinct XOR-subset-sums is 2ᵇ**, where `b` is the size of the basis. This is because the `b` basis vectors are independent, so each of the `2ᵇ` subsets gives a distinct XOR.

**2. If `b < d`, then not all `d`-bit values are reachable.** The span is a proper subspace.

**3. The span is closed under XOR.** If `x` and `y` are reachable, so is `x ⊕ y`. The span forms what's called a *vector subspace*.

**4. Any vector is either in the span or not**, there's no in-between. Checking membership: run the elimination loop above. If it reduces to 0, the vector is in the span.

**5. You can modify basis vectors without changing the span.** Specifically, XOR-ing one basis vector with another doesn't change what the basis can collectively express. This is what justifies the elimination step in the algorithm, we modify `v` freely before inserting it.

## A Small but Revealing Example

Let's build a basis for the set `{7, 5, 3, 6}` = `{111, 101, 011, 110}` in binary.

**Insert 7 = 111:**
- Bit 2 is set, `basis[2]` is empty. Place it: `basis[2] = 111`.

**Insert 5 = 101:**
- Bit 2 is set, `basis[2] = 111`. XOR: `101 ⊕ 111 = 010`.
- Bit 1 is set, `basis[1]` is empty. Place it: `basis[1] = 010`.

**Insert 3 = 011:**
- Bit 1 is set, `basis[1] = 010`. XOR: `011 ⊕ 010 = 001`.
- Bit 0 is set, `basis[0]` is empty. Place it: `basis[0] = 001`.

**Insert 6 = 110:**
- Bit 2 is set, `basis[2] = 111`. XOR: `110 ⊕ 111 = 001`.
- Bit 0 is set, `basis[0] = 001`. XOR: `001 ⊕ 001 = 000`.
- It reduces to 0, so 6 is already in the span and doesn't need to be inserted.

**Final basis:** `{7, 2, 1}` → size 3.  
**Span size:** 2³ = 8. All 3-bit values `{0, 1, 2, ..., 7}` are reachable.

## What You Now Know

You've just built up, from scratch, enough Linear Algebra to understand what's actually happening in one of the more elegant competitive programming techniques.

To recap:

- **ℤ₂** is arithmetic mod 2, where 1 + 1 = 0.
- **ℤ₂ᵈ** is the space of `d`-bit binary vectors under XOR.
- XOR of integers is **vector addition** in this space.
- The **span** of a set of integers is all XOR-sums of its subsets.
- A **basis** is the minimal set with the same span, found via Gaussian Elimination.
- A basis of size `b` implies a span of size **2ᵇ**.
